## 0. この仕様書の読み方

本書は、会話で方向性が合意された内容と、実装に向けた提案を区別する。

- **[合意]**: ユーザーとの会話で方向性が確認された事項。
- **[提案]**: MVP の実装案。着手前・実装中に変更してよい事項。
- **[未決]**: 検証や追加判断を要する事項。

数値や技術構成は、別途明記しない限り**目標・提案**であり、検証済みの性能値や既成事実ではない。

## 1. プロダクト概要

### 1.1 名称

- **正式なプロダクト名:** 地図の行間 **[合意]**
- **タグライン案:** 「世界を動かす。世界がわかる。」 **[提案]**
- **カテゴリ:** インタラクティブ地政学アトラス **[合意]**

### 1.2 コンセプト

**世界地図を操作し、国際情勢の背景にある地理的条件と国家間のつながりを自分で発見する探索型学習プロダクト。**

「出題 → 解答 → 正誤判定 → 解説 → 次の問題」という従来型のゲーミフィケーションから離れ、地図・レイヤー・条件・視点をユーザー自身が操作することを中心体験に据える。**[合意]**

### 1.3 提供価値

1. **見るだけでなく、触って理解する。** 地図上の条件を変更すると、関連する情報の表示が即座に変わる。
2. **一つの事象から関係性を発見する。** 海峡、航路、国家、資源、輸送の依存関係をたどる。
3. **事実と仮定を混同せずに考える。** 現実の地理情報と、仮想シナリオの表示・推論を区別する。
4. **自由な探索を尊重する。** 決められた正解や進行順を押し付けない。

### 1.4 想定ユーザー **[提案]**

- 国際ニュースの背景を理解したい、地政学の初学者。
- 地図・歴史・経済の関係を視覚的に学びたい人。
- クイズよりも、シミュレーション・探索・可視化を好む人。

### 1.5 ジョブ・トゥ・ビー・ダン（JTBD） **[提案]**

「ニュースで海峡・国境・資源の話題を見たとき、何が重要なのかを地図で確かめ、ほかの地域とのつながりまで自分で説明できるようになりたい。」

## 2. 体験設計の原則

### 2.1 やること **[合意]**

- **探索:** 地図から気になる場所・関係性を調べる。
- **実験:** 既定の仮定条件を切り替え、見え方の変化を観察する。
- **比較:** 変更前と変更後、あるいは国ごとの視点を比較する。
- **発見:** 予想していなかった依存関係を可視化する。
- **記録:** 自分の気づきをアトラス内に残す。

### 2.2 やらないこと **[合意]**

- 正解の選択肢を押さないと先へ進めない設計。
- XP、レベル、ランキング、バッジ、ログイン連続日数による進行管理。
- キャラクターやストーリー演出を中心にした学習体験。
- 根拠の薄い因果関係を「確定した事実」として表現すること。

### 2.3 デザイン原則 **[提案]**

- **地図が主役:** 画面面積の大半を地図に割き、情報パネルは必要なときに展開する。
- **操作に即応:** 状態の変更に対して地図・ラベル・関連情報が同期する。
- **「何が変わったか」がわかる:** 色や線種だけに依存せず、凡例と説明を併記する。
- **自分で問いを見つける:** 誘導的な「次の問題」より、関連地点・関連レイヤーへの導線を設ける。
- **不確実性を隠さない:** 事実・仮定・説明モデルの限界を明示する。

## 3. MVP のテーマと学習対象

### 3.1 最初のテーマ

**「マラッカ海峡の通行条件が変わったら、海上輸送の経路と地理的な制約はどう見えるか」** **[合意]**

地理的事実、海上輸送、代替航路を一つの画面で結びつける。「封鎖時に原油価格が何%上がるか」といった経済予測は扱わない。

### 3.2 MVP で届けたい学習体験

ユーザーが自発的に次を発見できること。

1. マラッカ海峡は、インド洋と東・東南アジアを結ぶ主要な海上交通路の一つである。
2. ある航路を使えないと仮定した場合、別の航路の検討が必要になる。
3. 代替航路は存在しても、距離・所要時間・船舶条件・輸送能力などの制約が残る。
4. 国によって貿易・エネルギーの依存構造は異なり、同じ事象でも注目点が異なる。

> **注意:** 上記は教材として扱う基本的な論点。公開時には各論点の出典、地理データの時点、航路表現の前提を確認する。

### 3.3 シナリオの定義

- **通常時:** 教材用に定義した主要航路の概念モデルを表示。
- **通行不可（仮定）:** マラッカ海峡を使えないと仮定し、事前定義した代替航路**候補**を可視化する。
- **表示上の意味:** 船舶が実際に自動で迂回するという予測ではない。条件によって検討すべき候補経路が変わることを示すモデル。
- **航路候補:** 初期案はロンボク海峡など。別候補の採否・実データに基づく描画は公開前に検証する。**[提案]**

### 4.1 F-01 地図表示

- 初回は東南アジアと周辺海域にフォーカスした範囲を表示する。**[提案]**
- 背景地図のパン・ズームに対して航路レイヤーが追従する。
- 対象の海峡、航路、関連地点を選択すると、該当する情報パネルが開く。
- 地理情報の描画には実座標を利用し、単なる概念図を正確な航路として誤認させない。

### 4.2 F-02 レイヤー切替

- `国境`、`主要航路`、`注目地点` の三種類を実装する。
- 各レイヤーは独立に表示・非表示を切り替えられる。
- レイヤーが消えている理由をユーザーが認識できるよう、トグル状態を明示する。

### 4.3 F-03/F-04 シナリオと可視化

- 状態は `normal` と `malacca_unavailable` の二値から開始する。
- 変更時は、航路表示・凡例・情報パネルの説明が一貫して切り替わる。
- **「通行不可」は演習上の仮定であり、現実の航行規制や将来予測ではない**と明示する。
- 代替航路候補は、裏付けのある事前定義データから表示する。実輸送量・実際の船舶経路を自動推定したものとして扱わない。
- 表示の変化には、何が変わったかがわかる短い説明を付ける。

### 4.4 F-05 比較表示

- MVP の最小仕様は、**状態切替＋差分ハイライト**。**[提案]**
- 可能なら「通常時」「仮定時」を左右に並べる比較モードを追加する。**[未決]**
- どちらのモードも双方の条件名が画面上で明確に判別できる。

### 4.5 F-06 情報パネル

最低限の表示項目：

- 名称、位置（地域）、短い解説。
- 関連する航路または地点。
- 現在のシナリオでの表示上の意味。
- `地理的事実` / `シナリオ上の仮定` / `説明・推論` の区分。
- 出典名、URL、対象の確認・更新日（可能な範囲）。

### 4.6 F-07 発見メモ

- ユーザーが任意のテキストを入力して保存できる。
- メモには保存時のシナリオ、レイヤー状態、選択地点、保存日時を紐づける。
- メモ一覧から選択すると当時の地図状態に戻せる。
- メモの削除ができる。
- MVP は端末・ブラウザ内保存とし、ログイン・クラウド同期は行わない。**[提案]**

## 5. 主要ユーザーフロー

### 5.1 初回探索

1. ユーザーがアプリを開く。
2. マラッカ海峡周辺の地図と主要航路が表示される。
3. 海峡や航路を選択し、説明と関連地点を確認する。
4. `通行不可（仮定）` に切り替える。
5. 地図上の航路候補と凡例が変わる。
6. 通常時と比べ、何が変わったかを確認する。
7. 気づきをメモに残す。
8. 必要に応じて他の地点・レイヤーを調べる。

**完了条件は設けない。** ユーザーは自由に探索を続けたり終了したりできる。

### 5.2 発見メモの再訪

1. 保存済みメモの一覧を開く。
2. メモを選ぶ。
3. 保存時のシナリオ・レイヤー・選択地点が再現される。
4. 続きを探索する、または新しいメモを作成する。

### 5.3 エラー/空状態

- 地図タイル・地理データが読み込めない場合、原因を断定せず再試行を案内する。
- 保存できない場合、メモ入力内容を可能な限り画面上に残し、保存失敗を明示する。
- メモがゼロの場合は空状態を表示する。不要な報酬や進捗演出は付けない。
- 対象データがない地点では「未収録」と表示し、欠損をゼロや無影響として扱わない。

## 6. 画面構成とインタラクション

### 6.1 PC 画面 **[提案]**

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 地図の行間                  [探索テーマ] [発見メモ] [設定/凡例]       │
├────────────────────────────────────┬────────────────────────────────┤
│                                    │ 探索パネル                       │
│                                    │ ─ レイヤー                       │
│           インタラクティブ地図       │   □ 国境                        │
│                                    │   ☑ 主要航路                    │
│       海峡・航路・関連地点を表示      │   ☑ 注目地点                    │
│                                    │ ─ シナリオ                       │
│                                    │   ○ 通常時                      │
│                                    │   ○ 通行不可（仮定）            │
│                                    │ ─ 比較表示                       │
├────────────────────────────────────┴────────────────────────────────┤
│ 選択中の地点 / 説明 / 出典 / 仮定の注意 / [発見メモを保存]             │
└─────────────────────────────────────────────────────────────────────┘
```

- 地図と右側探索パネルを基本レイアウトとする。
- 選択地点の説明は、右パネル内または下部の情報パネルに表示する。最終配置は実機検証で確定。
- 比較中も地図を見失わないよう、凡例と状態表示を固定的に配置する。

### 6.2 モバイル画面 **[提案]**

- 地図を主画面にする。
- 操作はボトムシートで表示する。
- シナリオ切替を最も見つけやすい位置に置く。
- 地図のズーム操作とスクロールを誤操作しにくいよう調整する。

### 6.3 ビジュアルの方向性 **[提案]**

- 知的で落ち着いた地図表現。過度な装飾やゲーム用キャラクターは使わない。
- 通常ルート、代替候補、未使用ルートを色・線種・凡例の組み合わせで区別する。
- アニメーションは因果・変更点の理解に必要な箇所に限定する。

## 7. 情報の信頼性と表現ルール

### 7.1 データの種類

| 種別 | 表示ラベル | 例 | 扱い |
|---|---|---|---|
| 確認可能な地理・歴史・統計 | `事実` | 海峡の位置、公開統計の数値 | 根拠と対象時点を付ける |
| ユーザーが変更した架空の条件 | `仮定` | マラッカ海峡が通行不可 | 現実の出来事と混同させない |
| 教材用の解釈・モデル | `モデル上の説明` | 代替航路候補を表示するルール | モデルの前提・限界を説明する |

### 7.2 やってはいけない表現

- 「通行不可にしたら原油価格が必ず上昇する」などの確実性を装う断定。
- 海峡が通れないと仮定しただけで、実際の輸送流量や国別被害額を算出したように見せる表現。
- 実座標に基づかない模式線を、実際の船舶航跡と表示すること。
- 国の意図や政府の「本音」を地理だけから断定すること。
- 出典がないデータを「最新」「正確」と宣言すること。

### 7.3 出典管理 **[提案]**

各コンテンツは最低限、`sourceId`、資料名、URL、参照日、データ対象期間、使用した情報の範囲を管理する。

候補となる一次・公的資料（**採用・ライセンス・最新版は未検証**）：

- 米国 EIA：海上石油輸送とチョークポイントに関する資料。
- UNCTAD：海運・貿易に関する公表資料。
- 国際水路機関（IHO）等の公開情報：地理的名称や海域の定義に関する資料。
- OpenStreetMap 等：地図表示用データ（利用条件・帰属表示の遵守が必要）。

**公開前に確認すること:** 原資料へのリンク、更新日、地理データのライセンス、航路ラインの根拠、地図タイル提供条件。

## 8. データモデル案 **[提案]**

初期段階はコンテンツと表示ルールを静的 JSON / GeoJSON で管理する。

### 8.1 エンティティ

| エンティティ | 主なフィールド | 用途 |
|---|---|---|
| `Location` | `id`, `name`, `type`, `geometry`, `description`, `sourceIds` | 海峡・港・国・注目地点 |
| `Route` | `id`, `name`, `geometry`, `routeType`, `sourceIds`, `limitations` | 通常ルート・代替候補 |
| `Layer` | `id`, `name`, `visibleByDefault`, `featureIds` | レイヤー表示 |
| `Scenario` | `id`, `label`, `assumptions`, `visibleRouteIds`, `highlightIds`, `explanation` | 条件変更による地図表示 |
| `ContentSource` | `id`, `title`, `url`, `accessedAt`, `dataPeriod`, `license` | 出典と権利情報 |
| `DiscoveryNote` | `id`, `body`, `createdAt`, `mapState` | 発見メモ |
| `MapState` | `scenarioId`, `visibleLayerIds`, `selectedFeatureId`, `viewport` | 現在の探索状態 |

### 8.2 シナリオデータの例（仮の ID。実座標・実データは含まない）

```json
{
  "id": "malacca_unavailable",
  "label": "通行不可（仮定）",
  "assumptions": [
    "教材上、マラッカ海峡を利用できないものとする"
  ],
  "visibleRouteIds": ["candidate-via-lombok"],
  "highlightIds": ["malacca-strait", "lombok-strait"],
  "explanation": "代替航路の候補を表示します。実際の船舶運航や経済影響を予測するものではありません。",
  "classification": "hypothetical"
}
```

### 8.3 メモの例

```json
{
  "id": "note-local-001",
  "body": "別の海峡があっても、輸送条件が同じとは限らない。",
  "createdAt": "2026-11-09T09:00:00+09:00",
  "mapState": {
    "scenarioId": "malacca_unavailable",
    "visibleLayerIds": ["routes", "points"],
    "selectedFeatureId": "lombok-strait",
    "viewport": { "longitude": 111.0, "latitude": -1.0, "zoom": 4 }
  }
}
```

> 例中の日時・表示範囲・ID はデータ構造を説明するためのダミー値。実測値ではない。

## 9. 技術構成案 **[提案・未確定]**

| 領域 | 候補 | 方針 |
|---|---|---|
| UI | React + TypeScript | コンポーネントと状態管理を明確に分離 |
| 地図エンジン | MapLibre GL JS | Web 上のパン・ズーム、地物表示と操作 |
| 地理データ | GeoJSON | 少数の地点・経路から始める |
| コンテンツ | JSON / Markdown | 事実と説明の更新を容易にする |
| 状態管理 | React state（必要に応じて専用ライブラリ） | シナリオ・レイヤー・選択地点を単一の状態として扱う |
| メモ保存 | `localStorage` または IndexedDB | MVP はサインインなし・ローカルのみ |
| バックエンド | なし | 静的 Web アプリとして開始可能 |

### 9.1 実装上の責務分離

1. `content/`: 出典付きの地理・説明データ。
2. `scenarios/`: 仮定・表示ルール・代替ルート候補。
3. `map/`: 地図描画とインタラクション。
4. `ui/`: パネル、レイヤー操作、比較、メモ。
5. `storage/`: メモの保存・読み込み・削除。

### 9.2 モデルの制約

初期実装は**ルールベースの教材用可視化**であり、船舶輸送の最適化計算、経済モデル、国家の行動予測を実装しない。航路候補は専門資料で検証した内容を事前定義する。

## 10. 非機能要件 **[提案]**

### 10.1 アクセシビリティ

- トグル・ラジオ・ボタンはキーボードでも操作できる。
- フォーカス表示、操作ラベル、スクリーンリーダー向けの意味付けを用意する。
- 航路の違いを色だけで表現しない。
- 地図による情報の要約をテキストでも確認できる。
- モーションを減らす設定への配慮を行う。

### 10.2 性能・対応範囲

- デスクトップブラウザを優先し、モバイルでも基本探索ができるレスポンシブ設計とする。
- シナリオ切替時に不要なページ遷移・再読み込みを発生させない。
- MVP は限られた GeoJSON データを初期ロードし、大量の世界規模データを要求しない。
- 具体的なロード時間・FPS の目標値は実装環境で測定して決定する。**[未決]**

### 10.3 プライバシー・セキュリティ

- 初期はアカウント・外部送信なしでメモを保存する設計を優先する。
- メモが端末内保存であり、別端末へ自動同期されないことを明示する。
- 外部から読み込む文章を HTML として無条件に実行・埋め込まない。
- 外部データと地図タイルについて提供元の利用条件・適切な帰属表示を守る。

## 12. ユーザーテスト計画 **[提案]**

### 12.1 目的

「説明を読まされる」のではなく、**触りたくなる・意外な関係に気づく**体験が成立するか検証する。

### 12.2 初回テスト

- 想定：地政学初学者を含む **5〜8人** への探索的ユーザーテスト。
- 誘導を最小限にして、自由に触ってもらう。
- 操作の迷い、最初の自発的アクション、発見の瞬間、メモの利用を観察する。
- テスト後、初見の別事例でも類似した視点を説明できるか確認する。

### 12.3 主な観察項目

- 何も指示されなくてもシナリオ切替を試したか。
- 変更前後の違いを説明できたか。
- 代替航路とその制約について自分の言葉で説明できたか。
- 追加で地図を触りたくなったか。
- 仮定を現実の事実と誤認していないか。

> この人数は UX 上の問題発見を目的とした案であり、学習効果を統計的に実証するための規模ではない。

## 13. 開発の進め方 **[提案]**

### Phase 0: 内容・データの検証

- マラッカ海峡・候補航路の出典を選定する。
- 対象地理情報の座標・形状・ライセンスを確認する。
- 通常時と仮定時で表示するルールをデータ化する。
- 事実とモデルの区別・免責の文言を整備する。

### Phase 1: 最小の操作体験

- 地図表示。
- 航路・地点の GeoJSON オーバーレイ。
- `通常時` / `通行不可（仮定）` の切り替え。
- 凡例・説明・表示変化の同期。

### Phase 2: 探索を深める

- 地点詳細・出典表示。
- 地図レイヤー切替。
- 比較モード。
- 発見メモの保存・再現。

### Phase 3: UX・品質の検証

- PC・モバイル・キーボード操作の確認。
- ファクトチェックと地図表示の妥当性確認。
- ユーザーテストと改善。

## 15. 将来の拡張 **[提案]**

拡張は「地図に触る → 関係性を発見する」という核を損なわない範囲で行う。

1. **依存関係レイヤー:** 貿易相手国、エネルギー、半導体などの関係性を表示。
2. **国別視点:** 同一の地理的変化を日本・中国・シンガポールなどの視点で観察。
3. **ネットワーク実験室:** ある接続を取り除いたときの影響範囲を、明示されたモデルに基づいて提示。
4. **歴史タイムライン:** 公開史料に基づき、国境・貿易ルートの変化を時間軸で可視化。
5. **複数地域の探索:** スエズ運河、パナマ運河、ホルムズ海峡などへテーマを拡張。
6. **発見の共有:** 保存した地図状態と注釈を共有する。

## 17. 開発開始前の最優先チェック

最初のコミットでは全機能を作るのではなく、次の **1つの縦断フロー** を成立させる。

> **地図を開く → マラッカ海峡を選ぶ → `通行不可（仮定）` にする → 代替航路候補が表示される → 差分とモデルの限界がわかる。**

このフローを使って「触ることで理解が深まる」ことを確認してから、情報レイヤーと発見メモを加える。

**プロダクトが実現するべき一文:**

> 世界の出来事に対し、単一の説明を覚えるのではなく、地図上の条件とつながりを確かめ、自分で関係性を発見できるようになる。
