# 初見ユーザーテスト計画（UX-10）

目的は定性的な課題発見。統計的な有意性は主張しない。対象は地政学の初心者を含む初見ユーザー 5〜8 人。説明なしで公開 MVP（https://ysj101.github.io/chizu-no-gyokan/）を使ってもらい、迷った場所・読まなかった説明・誤解した表示を記録する。

## 実施条件

- 端末：参加者の普段の端末（PC とスマートフォンを半々程度）。可能なら 1 人はテキスト拡大（OS 設定 150% 以上）、1 人はキーボードのみ、1 人はスクリーンリーダー（VoiceOver または NVDA）で実施する。
- 進行役は操作を教えない。質問には「どう思いますか」と返す。詰まって 2 分進まない場合だけ次のタスクへ進める。
- 記録は画面の録画（同意がある場合）と観察メモ。氏名は記録しない（参加者 ID のみ）。

## 手順

1. **3 秒テスト**（初期画面を 3 秒見せて隠す）：「何ができる画面でしたか」「最初に何を触りますか」。
2. **自由探索 2 分**：どこを見たか、何を押したかを記録する。
3. **主要タスク**（順不同で可。各タスク後に「何が起きましたか」を一言で言ってもらう）
   - T1 条件を切り替える：「マラッカ海峡を通れないと仮定した地図にしてください」
   - T2 何が変わったか説明する：「今の地図で、通常時と何が変わったか説明してください」
   - T3 関連地点を見る：「マラッカ海峡の説明から、関係のある別の場所を 1 つ開いてください」
   - T4 メモを保存・復元する：「気づいたことをメモに残し、地図を変えてから、そのメモの状態に戻してください」
   - T5 国ごとの視点：「日本から見るとこの海峡がどういう意味か、画面で確かめてください」
4. **事後の確認**（口頭）：「破線の航路は実際の船の通り道だと思いましたか」「通行不可は現実の出来事だと思いましたか」「数字が出てきたら、それがいつのものか分かりましたか」
5. **終了後 5 分以内**に観察メモを `docs/user-test-log.md` の記録表へ転記する。

## 観察の観点（UI 設計ガイドライン第 9 章に対応）

| 観点 | 記録すること |
| --- | --- |
| 3 秒テスト | 画面の目的と最初の操作を言えたか |
| 文言 | 読まなかった説明、意味を取り違えた語（例：仮定／モデル／非表示） |
| 操作結果 | 操作の前に結果を予測できたか、操作後に状態が分かったか |
| 配置 | 探した場所と実際の場所のずれ、スクロールの往復 |
| キーボード | Tab の順序で迷った箇所、フォーカスが見えなかった箇所、行き詰まり |
| 読み上げ | 状態（押下中・表示中）と操作（押すと何が起きるか）を区別して聞き取れたか |

## 判定と比較

- タスクごとに「できた／助けありでできた／できなかった」と所要時間（分）を記録する。
- T2 は「追加・変更・非表示のうち何個を自分の言葉で言えたか」（0〜3）で記録し、改善前後の比較観点とする。
- 事後確認の 3 問は「誤解あり／なし」で記録する（事実・仮定・モデル・未収録の区別の指標）。

## 結果の扱い

- 迷い・誤解は再現手順（端末、条件、操作列、期待と実際）つきで `docs/qa-log.md` の所見表に追加し、優先度（P0：誤解を招く／P1：主要タスクが止まる／P2：改善余地）と対応予定を付ける。
- 対応するものは Issue に分解し、`features/` の該当文書と E2E を更新する。
- 参加者の発言は要約し、個人が特定できる情報は残さない。
