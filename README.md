# 地図の行間

**世界地図を操作し、国際情勢の背景にある地理的条件を自分で発見する、探索型の学習プロダクトです。**

最初のテーマは「マラッカ海峡と海上輸送」。海峡を使えないと仮定したとき、検討すべき航路候補がどう変わるかを地図上で確かめられます。

🌏 **公開サイト:** https://ysj101.github.io/chizu-no-gyokan/

## このプロダクトについて

ニュースで「海峡」「航路」「チョークポイント」という言葉を見かけても、それがなぜ重要なのかは地図を見ないとわかりません。地図の行間は、クイズや正解当てではなく、**地図を自分で動かし、条件を切り替え、変化を観察する**ことを中心に据えた教材です。

大切にしていること:

- **地図が主役。** 画面の大半を地図に使い、情報は必要なときに展開します。
- **事実と仮定を混同しない。** 地理的事実、シナリオ上の仮定、説明・推論を区別して表示します。
- **根拠を隠さない。** 表示する情報には出典と対象時点を添え、モデルの前提と限界を明記します。
- **自由な探索を尊重する。** 決められた順番や正解はありません。

## できること

| 機能 | 内容 |
|---|---|
| 地図探索 | マラッカ海峡周辺を実座標の地図でパン・ズームし、海峡・航路・関連地点を選んで説明を読む |
| 条件実験 | 「通常時」と「通行不可（仮定）」を切り替え、航路候補・凡例・説明がどう変わるかを比べる |
| 詳細と根拠 | 選択した対象の位置、関連する航路や地点、現在の条件での意味、出典と注意事項を確認する |
| レイヤー切替 | 国境・主要航路・注目地点を個別に表示・非表示にする |
| 発見メモ | 気づきを、そのときの地図の状態（条件・レイヤー・選択・表示範囲）と一緒にブラウザ内へ保存する |
| 状態の復元 | 保存したメモから当時の地図の状態に戻り、そこから探索を続ける |
| 国ごとの視点 | 日本・シンガポール・中国・インドネシアを例に、同じ海峡の意味を資料（EIA）に沿って比べる。事実と読み取りを分け、国家の意図は断定しない |

メモはお使いのブラウザの中だけに保存されます。アカウント登録は不要で、入力内容が外部へ送信されることはありません。

## 表示内容についての注意

- 航路は、公開資料に基づいて著者が作成した**概略モデル**です。実際の船舶の航跡ではなく、航行の案内には使えません。
- 「通行不可」は学習のための仮定であり、現実の航行規制や将来の予測ではありません。
- 輸送量・所要時間・船舶条件・経済影響などの数値は扱っていません。表示がないことは「影響がない」ことを意味しません。
- 国境・海岸線は小縮尺向けに一般化されたデータで、高いズームでの精度や政治的な承認を表すものではありません。

## 手元で動かす

Node.js 22 以上が必要です。地理データの検査を実行する場合は Python 3 も使います。

```sh
npm ci
npm run dev        # http://127.0.0.1:5173
```

ビルドと検証:

```sh
npm run typecheck      # 型検査
npm test               # ユニットテスト
npm run test:privacy   # メール保護スクリプトのテスト（Python）
npm run test:geometry  # 地理データの整合性検査（Python）
npm run build          # dist/ へビルド
npm run preview        # ビルド結果を http://127.0.0.1:4173 で確認
```

ブラウザを実際に動かす E2E テストと一括検証:

```sh
npx playwright install chromium
npm run verify
```

`npm run verify` はビルド済みのプレビューを起動し、PC とモバイルの画面幅で Playwright による操作と画面撮影を行い、結果を `artifacts/map-exploration/`（Git 管理外）へ保存します。個別の手順は [features/](features/README.md) 配下の各ドキュメントにまとめています。

## 技術構成

- TypeScript（strict）+ [Leaflet](https://leafletjs.com/) 1.9.4 + Vite。フレームワークは使っていません。
- 外部タイルサーバーや API、API キーは使いません。地図の背景データは同じオリジンから配信し、外部へ通信するのは利用者が出典リンクを開いたときだけです。
- 設計の経緯は [docs/architecture.md](docs/architecture.md)、プロダクト仕様は [docs/spec.md](docs/spec.md) を参照してください。

### デプロイ

`main` ブランチへ push すると、GitHub Actions が自動でビルドして GitHub Pages に公開します（[.github/workflows/pages.yml](.github/workflows/pages.yml)）。ビルド時に `BASE_PATH` 環境変数で公開パスを指定しています。

### CI とメールアドレス保護

`CI` ワークフローはすべての push と PR で動き、テスト・ビルド・E2E に加えて、コミットの author・committer・メッセージ・PR 本文に個人のメールアドレスが含まれていないかを検査します。許可されるのは GitHub の noreply アドレスなどに限られます。手元で確認するには:

```sh
sh scripts/check-email-privacy.sh BASE..HEAD
```

## 出典と権利

- **国境データ:** [Natural Earth](https://www.naturalearthdata.com/) v5.1.2（1:50m, admin 0 countries）。パブリックドメイン。必要な 14 か国と属性だけを抽出して配布しており、[scripts/import-geography.py](scripts/import-geography.py) で元データから再生成できます。
- **航路候補の根拠:** [U.S. EIA, World Oil Transit Chokepoints](https://www.eia.gov/international/content/analysis/special_topics/world_oil_transit_chokepoints/)（2026-03-03 更新）。スンダ・ロンボク両海峡を代替経路として挙げている記述のみを採用し、統計・図・画像は転載していません。米国政府出版物として[パブリックドメイン](https://www.eia.gov/about/copyrights_reuse.php)です。
- **Leaflet:** BSD-2-Clause。ライセンス全文は配布物の [NOTICE.txt](public/NOTICE.txt) に含め、アプリのフッターからリンクしています。

航路の点列、地点の代表座標、日本語の国名・ラベル、およびこのリポジトリのコードは著者が作成したもので、**再利用ライセンスは現時点で未設定**です。Natural Earth と EIA のパブリックドメインはこれらの自作部分には及びません。利用をご希望の場合は Issue でご連絡ください。

## 現在の状態

MVP の主要機能は実装済みですが、次の点はまだ行っていません。

- 国ごとの視点切替、メモの共有・エクスポート、追加シナリオ（スエズ運河など）
- 利用者による自由探索のフィードバック収集、スクリーンリーダーでの実機確認

自動テストと画面確認は通っていますが、教材としての受け入れ評価はこれからです。気づいた点があれば Issue でお知らせください。
